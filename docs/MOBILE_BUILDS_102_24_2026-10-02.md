Confirmed diagnostic limitation: the installed React Native 0.86.3 Android
NetworkingModule forwards response code/headers/URL, not OkHttp response.message,
through NetworkEventUtil to XMLHttpRequest. XMLHttpRequest has no statusText
implementation, while whatwg-fetch obtains its Response.statusText from that
missing field. The app's `cache_only_signature` depends on exact statusText.
Therefore false does NOT exclude OkHttp's synthetic only-if-cached 504. Candidate
source map includes the inspected React Native XMLHttpRequest/fetch path. This
is a diagnostic bug/limitation, NOT proof that native cache caused this event.
Proposed next work: native-equivalent reproduction and privacy-bounded transport
classification, distinguish unavailable status text from a negative match,
test real HTTP504/local synthetic504/offline/reconnect/account-switch recovery,
then repair only the demonstrated fault. No runtime code changed in that audit.
